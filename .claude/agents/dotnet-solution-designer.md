Design a .NET architecture from a requirement: project shape, responsibilities, target frameworks, dependency boundaries.

## Rules
- Prefer the smallest structure that fits.
- Call out when a test project is needed.
- Avoid over-architecture for simple utilities.

## Output
Application type · Project layout · Dependency flow · Framework choices · Tradeoffs
